# 构建说明

> ★ 本仓是**源码**形态（约 350 KB）。想要「双击就能用、不用装 Python」的成品，需要打一个包。
> ★★ 本节说明**怎么打**，以及**为什么本仓不直接放成品**。

---

## 为什么本仓不带 `python/`

一份可用的成品包约 **101 MB / 2,883 件**，其中：

| 部分 | 体积占比 |
|---|---|
| `python/` 便携运行时 | **约 95%**（904 件） |
| `app/` 真代码 | **约 0.35%**（9 件） |

★ 把 904 个第三方文件塞进仓库，会让 `git clone`、`git log`、代码审查全部变慢；而它们**没有一行是本项目的代码**。
★★ 故本仓只放源码，成品由你按下面几步现打。

---

## 打成品包

### 1 · 准备一份便携 Python

用 [python-build-standalone](https://github.com/astral-sh/python-build-standalone) 或 Windows 版 embeddable Python，
解压到本仓同级目录，命名成 `python/`：

```
python/
├─ python.exe
├─ pythonw.exe        ← ★ 桌面窗口要用这个（无控制台）
└─ …
```

### 2 · 装四个依赖进去

```bash
python\python.exe -m pip install --target python\Lib\site-packages fastapi uvicorn pydantic httpx
```

### 3 · 复制本仓到成品目录

把源码目录整个复制一份（推荐命名成 `拆解器_v0.1/`），再从第 1、2 步把 `python/` 放进去。

### 4 · 清掉不该进成品的

按**点名清单**删（★ **不要用通配** —— 通配会越权）：

| 删什么 | 为什么 |
|---|---|
| `app/**/__pycache__/` · `python/**/__pycache__/` | ★★ **`.pyc` 里内嵌编译当刻的绝对路径** —— 这是最直接的本地信息泄漏源，而**看文件名完全看不出来** |
| `python/Lib/site-packages/pip/` | 13 MB + 6 个 Windows 可执行文件。本应用**从不 import 它** |
| `python/Scripts/*.exe` | 入口壳 exe。应用用 `python app/server.py` 启动，一个都用不上 |
| 任何 `.env.local` · `config.local.json` | ★★★ **那是你自己的 Key。成品包里不许有** |

### 5 · 最后一步：**真跑一次**

★ **静态全绿 ≠ 能跑。** 删完必须双击 `启动拆解器.bat`，看到窗口、发一句话、看到回答。

---

## 桌面窗口是怎么开的

`dissector.pyw` 会做三件事：

1. **无黑窗** —— 用 `pythonw.exe` 起服务（不是 `python.exe`）；
2. **独立窗口** —— 用 Edge/Chrome 的 `--app=` 开一个**无地址栏、无标签页、独立任务栏图标**的窗口；
3. **起不来要看得见** —— `pythonw` 会把 stdout/stderr 全丢掉，故它把失败写进 `日志·拆解器.log` **并弹一个对话框**。

`启动拆解器.bat` 按这个顺序找 Python：

```
① 本目录 python\pythonw.exe   （成品包）
② 系统 pythonw                （源码形态 —— 你装了 Python 就有）
③ 落到 FALLBACK：服务开在控制台窗口里、页面用默认浏览器
```

## 一个已知限度

★ 本仓**没有自动化构建脚本**。上面的步骤是**手工的**，因为我（作者）只在 Windows 上打过这一个包。

★★ 而那份 20 个脚本的构建目录**没有随本仓发布** —— 理由：它们写的全是作者机器上的绝对路径（`D:\…`），
脱敏之后**就不再能复现那个包**了。★ **一份脱敏后无法复现的构建脚本，价值低于这份说明。**

若你要做持续发布，建议新写一套**只依赖相对路径**的脚本，并把它放进 `scripts/`。
